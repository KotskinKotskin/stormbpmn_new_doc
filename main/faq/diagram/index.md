ℹ️🔽 "Автонумерация элементов диаграммы"

    Автонумерация присваивает элементам диаграммы уникальные порядковые номера в соответствии с их расположением.

    По умолчанию автонумерация выключена, чтобы её включить, кликните по {{ process_editor.right_toolbar.buttons.extra }} и из выпадающего списка выберите нужный вам вариант нумерации:

    - {{ process_editor.upper_toolbar.extra.num_tasks }} — нумеровать только задачи в пулах. Это удобно, когда пул большой и нужно видеть только то, что нужно.
    - {{ process_editor.upper_toolbar.extra.num_all }} — нумеровать все элементы диаграммы, включая пулы. Этот вариант нумерации обычно используют для работы с регламентами.

    ![]({{ media.screenshots.diagram }}/{{ media.actions.diagram_num_elements }}/diagramm_num_elements.png)

    **Нумерация элементов внутри пула**

    Нумерация элементов в пределах одного пула начинается с левого верхнего угла пула и продвигается в направлении правого нижнего угла зигзагом:

    1. Находится самый верхний левый элемент.
    1. Элементы нумеруются сверху вниз.
    1. Достигнув нижней границы пула, алгоритм сдвигается вправо и вверх, после чего продолжает нумерацию снова сверху вниз.
    1. Процесс повторяется до тех пор, пока не будут пронумерованы все элементы пула.

    **Нумерация пулов**

    Пулы нумеруются по аналогичному принципу — начиная с самого левого верхнего пула.
    Отличие заключается в определении порядка пулов: для этого алгоритм ориентируется на правую границу каждого пула. Пул, у которого правая граница расположена левее, считается «раньше» закончившимся и получает меньший порядковый номер.

    **Формат номеров**

    1.1 — первый элемент первого пула. **Первая цифра** — номер пула (пулы нумеруются слева направо и сверху вниз). **Вторая цифра** — порядковый номер элемента внутри пула (элементы нумеруются сверху вниз и слева направо по описанному выше алгоритму «заборчиком»).

    **Нумерация исходящих потоков из шлюза (Gateway)**

    Если элементом является шлюз, то для каждого исходящего из него потока (Sequence Flow) добавляется дополнительный уровень нумерации. Например, если шлюзу присвоен номер 1.5, то исходящие из него потоки получат номера:
    
    - 1.5.1 — первый исходящий поток;
    - 1.5.2 — второй исходящий поток;
    - 1.5.3 — третий исходящий поток и т.д.

    Порядок присвоения номеров потокам соответствует порядку их расположения (обычно слева направо или по направлению потока).

ℹ️🔽 "Исправление ошибки: Событие отправки без исходящего потока сообщений"

    Эта ошибка возникает, если не указать исходящий поток сообщений, ведущий в другой процесс, например так:

    ![]({{ media.screenshots.diagram }}/{{ media.actions.diagram_fix_error_44 }}/fix_error_44.png)

    Важно, чтобы исходящий поток сообщений приходил в конкретный активный элемент (стартовое событие или задача) в другом процессе или в свернутый подпроцесс.

    Данная ошибка не критичная, её можно не исправлять, а уведомление — отключить для всех диаграмм. Для отключения уведовления:
    
    1. Перейдите в раздел {{ team.icon }} {{ universal.right_arrow }} {{ team.team_settings.icon }} {{ universal.right_arrow }} {{ team.team_settings.general_settings }}:

        ![]({{ media.screenshots.diagram }}/{{ media.actions.diagram_fix_error_44 }}/switch_off_err_44.png)

        ![]({{ media.screenshots.diagram }}/{{ media.actions.diagram_fix_error_44 }}/switch_off_err_44_step_02.png)
