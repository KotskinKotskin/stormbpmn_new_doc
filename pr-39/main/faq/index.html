Подпроцесс по событию

Подпроцесс по событию в BPMN 2.0 — это тип подпроцесса, запускаемого конкретным событием (сообщением, ошибкой, сигналом или таймером) во время выполнения родительского процесса, с возможностью прерывания или параллельного выполнения для обработки исключений и уведомлений.

С его помощью можно организовывать пространство внутри пула. Например, можно расширить пул вправо с автоматическим переносом части элементов. Для этого выберите Управление пространством, кликните нужную вам часть пула и потяните её вправо:

Автонумерация элементов диаграммы

Автонумерация присваивает элементам диаграммы уникальные порядковые номера в соответствии с их расположением.

По умолчанию автонумерация выключена, чтобы её включить, кликните по и из выпадающего списка выберите нужный вам вариант нумерации:

  • Нумеровать только задачи — нумеровать только задачи в пулах. Это удобно, когда пул большой и нужно видеть только то, что нужно.
  • Нумеровать всё — нумеровать все элементы диаграммы, включая пулы. Этот вариант нумерации обычно используют для работы с регламентами.

Нумерация элементов внутри пула

Нумерация элементов в пределах одного пула начинается с левого верхнего угла пула и продвигается в направлении правого нижнего угла зигзагом:

  1. Находится самый верхний левый элемент.
  2. Элементы нумеруются сверху вниз.
  3. Достигнув нижней границы пула, алгоритм сдвигается вправо и вверх, после чего продолжает нумерацию снова сверху вниз.
  4. Процесс повторяется до тех пор, пока не будут пронумерованы все элементы пула.

Нумерация пулов

Пулы нумеруются по аналогичному принципу — начиная с самого левого верхнего пула. Отличие заключается в определении порядка пулов: для этого алгоритм ориентируется на правую границу каждого пула. Пул, у которого правая граница расположена левее, считается «раньше» закончившимся и получает меньший порядковый номер.

Формат номеров

1.1 — первый элемент первого пула. Первая цифра — номер пула (пулы нумеруются слева направо и сверху вниз). Вторая цифра — порядковый номер элемента внутри пула (элементы нумеруются сверху вниз и слева направо по описанному выше алгоритму «заборчиком»).

Нумерация исходящих потоков из шлюза (Gateway)

Если элементом является шлюз, то для каждого исходящего из него потока (Sequence Flow) добавляется дополнительный уровень нумерации. Например, если шлюзу присвоен номер 1.5, то исходящие из него потоки получат номера:

  • 1.5.1 — первый исходящий поток;
  • 1.5.2 — второй исходящий поток;
  • 1.5.3 — третий исходящий поток и т.д.

Порядок присвоения номеров потокам соответствует порядку их расположения (обычно слева направо или по направлению потока).

Работа с файлами и с рабочим пространством Stormbpmn

Перемещение диаграмм между папками

При создании аккаунта автоматически создаётся команда и рабочее пространство команды с папкой по умолчанию Others, в которую по умолчанию сохраняются диаграммы, если не указана другая папка.

Перемещение диаграммы между папками в разделе Команда

  1. Для перемещения диаграммы после её сохранения без указания конкретной папки или для перемещения между папками перейдите в раздел Команда → Модели бизнес-процессов → Папки:

  2. Перейдите в папку, где сейчас находится диаграмма, которую нужно перенести, или в папку Others, если диаграмма была сохранена без указания папки.

  3. Кликните на строку с названием диаграммы (не кликайте по самому названию — это откроет диаграмму в режиме редактирования), затем кликните на кнопку Переместить в верхней панели инструментов:

  4. В открывшемся модальном окне Переместить процессы выберите папку, в которую нужно перенести процессы, и нажмите кнопку Переместить процессы:

Если нужно переместить несколько процессов — кликайте по строке каждого процесса, который требуется перенести. Выбор по строке работает в режиме мультивыбора.

  1. Откройте диаграмму в редакторе и нажмите на кнопку Сохранить как версию в верхней панели инструментов:

  2. В открывшемся модальном окне Сохранение модели из выпадающего списка Название папки выберите нужную папку и нажмите кнопку Сохранить как версию:

Команда

Реестр бизнес-процессов

Дерево / Каталог

Что такое Дерево / Каталог?

Раздел Дерево / Каталог содержит инструменты для создания и управления карточками бизнес-процессов. В разделе доступны два вида представления процессов:

  • Дерево удобно использовать для создания сложных процессов с подпроцессами, а также для организации корневых процессов с переиспользуемыми подпроцессами.
  • Каталог предназначен для систематизации уже созданных бизнес-процессов по логическим или структурным признакам.
Дерево

В разделе Дерево для каждого процесса можно задать следующие свойства и параметры:

  • Показатели — вкладка с показателями процесса. Здесь можно добавлять, искать, редактировать и удалять метрики, по которым оценивается эффективность процесса: длительность, стоимость, количество ошибок, конверсия, LTV, скорость потока, число сделок. Эти показатели помогают сравнивать состояние процесса в разные периоды и находить узкие места.
  • Параметры — вкладка с параметрами процесса. Здесь хранятся пользовательские атрибуты и контекст: уровень риска, приоритет, критичность, продукт, проект, плановая дата запуска. Параметры можно создавать, выбирать из ранее созданных и редактировать, чтобы адаптировать карточки процессов под специфику вашей компании.
  • Документы — вкладка с документами процесса. Здесь удобно хранить входные, внутренние и выходные документы, связанные с процессом: регламенты, инструкции, положения, методики, шаблоны, формы и подтверждающие файлы. Это помогает сохранить в одном месте схему и её документальный контекст.
  • Модели BPMN — вкладка со связанными BPMN-моделями. Одна карточка процесса может быть связана с несколькими диаграммами, например с текущей моделью, архивной версией или целевой TO-BE-схемой. Это позволяет вести процесс как единую сущность при изменении графического описания.
  • Регламент — вкладка для формирования регламента процесса. Она собирает сведения из карточки процесса и связанных моделей, чтобы выгрузить их в текстовый регламент в формате DOCX.
  • Изменения — вкладка с историей изменений карточки процесса. Помогает отследить, какие параметры, показатели или состояния процесса менялись с течением времени.

Добавление параметров, показателей и документов к карточке процесса помогает превратить процесс в рабочий управленческий объект: понятный для исполнителей, прозрачный для владельца и удобный для анализа, улучшения и регламентации.

Каталог Каталог — это удобная форма организации процессов по каталогам. При этом разные каталоги могут содержать одни и те же процессы. Например, можно создать каталог Работа с клиентом и поместить туда процессы:
  • Подготовка договора
  • Согласование договора с клиентом
  • Подписание договора

Также можно создать каталог Процессы на улучшение и поместить туда, например, процесс Подготовка договора для пересмотра и улучшения:

Структура папок может быть плоской — все папки на одном уровне, нет вложенных папок, или иерархической — есть вложенные папки. При этом один и тот же процесс может встречаться несколько раз в одной структуре.

Роли

Ограничения прав и подписки

Создавать роли может только администратор команды. Роли — это часть платной подписки TEAM или Enterprise.

Поведение Ролей

Роли — это объекты команды, а не пользователя. При выходе из команды или переходе в другую команду роли удаляются с диаграмм, и их оверлеи на диаграммах пропадают (восстановление невозможно).

Общие сведения о ролях

Роль — это исполнитель конкретной задачи, а не должность. Одна роль может подходить для нескольких должностей: например, "Инициатором закупки товаров" может быть офис-менеджер, бухгалтер или завхоз. Наоборот, одна должность (как директор) может выполнять несколько ролей — от административных до юридических или бухгалтерских.

Роли переиспользуемы и предпочтительнее дорожек для описания исполнителей.

Редактирование ролей

Роли располагаются в разделе Роли. Там же их можно редактировать, нажав на кнопку Редактировать. После нажатия на кнопку откроется модальное окно Создание роли, в котором можно задать:

  • Название роли (обязательное поле) — поддерживается кириллица, латиница, специальные символы (автоэкранируются).
  • Тип роли (обязательное поле) — один из трёх вариантов типов роли: Человек, Система, Не указано.

Должность присваивается Роли в разделе Оргструктура Схема, а Роль задействуется в Процессе с помощью Редактора диаграмм.

Справочник

Что такое Справочник

Справочник — это набор заранее определенных пользовательских значений. Справочники используются для организации логически схожей информации. Проще всего представить справочник в виде выпадающего списка, в котором можно выбрать одну или несколько записей для отображения.

Поля справочника могут быть заполнены любыми типами данных (строки, целые числа, числа с плавающей точкой, логические (булевы) значения и прочие), которые будут преобразованы в строковые данные.

Справочники не поддерживают выполнение математических или логических операций над значениями.

Создание справочника

Справочники могут использоваться как наборы пользовательских параметров процессов. Например, можно задать категорию процесса или его статус. Чтобы создать справочник:

  1. Перейдите в раздел Команда Справочник.

  2. Нажмите кнопку Создать справочник.

  3. В открывшемся модальном окне Создание справочника заполните следующие поля:

    • Название справочника — ёмкое и понятное название. Учтите, что справочник будет представлен в виде выпадающего списка — название должно отражать суть его элементов.
    • Примечание — описание справочника; может содержать пояснения к элементам, их свойства или отличия.
    • Значения справочника — элементы справочника, которые будут доступны для выбора при работе со справочником. Количество элементов не ограничено, тип данных — любой.

  4. Нажмите кнопку Создать.

Созданный справочник автоматически будет отражён в разделе Справочник:

Использование справочника как параметра процесса

  1. Перейдите в раздел Команда Дерево / Каталог.

  2. Выберите бизнес-процесс, к которому хотите добавить справочник, перейдите во вкладку Параметры карточки бизнес-процесса и нажмите Добавить параметр:

  3. В открывшемся модальном окне Добавление параметра нажмите .

  4. На шаге Создание параметра выберите Тип параметра: Одиночный выбор для представления справочника в виде выпадающего списка с возможностью выбора одной записи или Мульти-выбор для выбора нескольких значений справочника.

  5. После выбора типа параметра в форме появятся новые поля:

    • Название — укажите название параметра. Оно будет отображаться в Параметры.
    • Подсказка для ввода — пояснение для выбора значений параметра.
    • Справочник — выбор справочника для привязки к параметру карточки процесса.
    • Примечание — дополнительное описание параметра.

  6. Нажмите кнопку Сохранить, затем Добавить.

  7. После добавления параметра к процессу он будет отражён в секции Параметры:

  8. Активируйте поле Значение не установлено и выберите нужное значение из выпадающего списка.

После первой привязки справочника к процессу и назначения ему имени как параметру, справочник можно добавлять к другим процессам через кнопку Добавить параметр.

Что такое Пользовательские поля? Пользовательские поля — это перечень всех возможных атрибутов и параметров процесса, которые позволяют настроить реестр процессов в соответствии со спецификой отрасли или компании.

Типы параметров

Простые типы данных

  • Текст — краткое текстовое описание для коротких значений (название, код, идентификатор). Подходит для коротких записей в одну строку.
  • Большой текст — многострочный текстовый ввод для длинных описаний, комментариев или заметок. Идеально подходит для детального описания или развернутых пояснений. Тип поля: текст.
  • Да/Нет — логический тип для булевых параметров. Удобен для бинарных признаков и флагов (например, "Обязательно", "Активно", "Утверждено").
  • Число — числовое значение для ввода количественных данных. Подходит для значений размера, количества, стоимости и других числовых метрик.
  • Дата — календарная дата без указания времени. Используется для указания сроков, дат начала или окончания событий (например, дата запуска процесса, дедлайн).
  • Дата/Время — дата и время для указания точного момента события. Необходимо, когда важна не только дата, но и время (например, время начала задачи, момент завершения этапа).

Исчисляемые и относительные единицы

  • Метрика — показатель для измерения эффективности процесса. Требует указания направления изменения (больше лучше / меньше лучше) и единицы измерения (руб., %, дни и т.д.). Отражается во вкладке Показатели бизнес-процесса.

Выбор из заранее подготовленных справочников

  • Одиночный выбор — позволяет выбрать одно значение из справочника. Справочник — это список заранее определенных значений. Например, справочник "Статус процесса" может содержать значения: "В разработке", "На согласовании", "Утвержден". Справочники могут содержать вложенные справочники для создания иерархической структуры данных.
  • Мульти-выбор — позволяет выбрать несколько значений из справочника одновременно. Полезно, когда параметр может иметь несколько вариантов ответа. Например, для параметра "Ответственные подразделения" можно выбрать несколько подразделений из справочника: "IT-отдел", "Финансовый отдел", "Отдел продаж".

Ссылки на заранее созданные объекты бизнес-процессов

  • Сотрудники — ссылка на конкретного сотрудника в системе. Используйте этот тип, когда параметр должен хранить именно человека (например, куратор процесса).
  • Элемент оргструктуры — ссылка на подразделение или позицию в оргструктуре. Подходит, если нужно хранить организационную единицу (например, ответственное подразделение).
  • Элемент архитектуры — ссылка на архитектурный объект (систему, приложение и т.п.). Используйте, когда параметр описывает связанную систему или ИТ-актив.
  • Роль (исполнитель) — ссылка на роль исполнителя процесса/активности. Подходит для хранения ответственных ролей.
